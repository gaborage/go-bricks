# Breaking changes index

GoBricks breaks its own API surface when justified. Greenfield work uses the new APIs only. **The lines below are an index, not the migration** — entries carry a tracked ADR (`wiki/adr_NNN_*.md`) or a `wiki/migrations.md` atom, and hops that need one have a table in [wiki/migrations.md](../../../wiki/migrations.md). Read those before upgrading. Every `fix(scope)!:` adds a line here, newest last, next to its ADR and atom.

- **S8179 (getter naming):** `GetX()` → `X()` across all packages.
- **S8196 (interface naming):** `Job` → `Executor`, `HealthProbe` → `Prober`, `TenantStore` → `DBConfigProvider`.
- **ToSQL standardization (ADR-017):** Insert builders return `types.InsertQueryBuilder` with `ToSQL()`.
- **Session timezone (ADR-016):** default `UTC`; opt out with `database.timezone: "-"`.
- **Consumer concurrency (v0.17.0):** default workers `1` → `NumCPU * 4`; set `Workers: 1` when ordering matters.
- **Message error handling (v2.X):** handler errors and panics nack messages without requeue.
- **MongoDB removed (ADR-012):** PostgreSQL and Oracle only.
- **Bounded publish + outbox dead-lettering (ADR-033):** publish returns `ErrPublishRetriesExhausted` after the new `messaging.reconnect.maxpublishattempts` — match with `errors.Is`, not `==`. `outbox.Store.FetchPending` drops `maxRetries`, gains `MarkDeadLettered`. New key: `outbox.publishtimeout`.
- **Env policy (ADR-022):** `app.env` accepts any conforming string; behavior switches go through `config.IsDevelopment()` / `config.IsProduction()` alias sets, never equality.
- **CORS dev wildcard opt-in (ADR-038):** the dev reflect-any-origin posture also requires `CORS_DEV_WILDCARD=true`; without it, dev fails closed.
- **Composite resolver order required (ADR-039):** `multitenant.resolver.order` is mandatory — no default.
- **Declaration Args reach the broker (ADR-040):** declare methods take `(ctx, *…Declaration)` and forward `Args`; may surface `406 PRECONDITION_FAILED` against ops-provisioned queues.
- **Database absence vs misconfiguration (ADR-047):** the `database:` block is all-or-nothing — omitting it is supported (`/ready` reports `not_configured`, 200), but any identity field (`type`, `host`, `port`, `database`, `username`, `password`, `connectionstring`, `oracle.service.name`, `oracle.service.sid`) marks it intended, and an incomplete intended block fails startup. Modules needing a database implement `app.DatabaseRequirer`.
- **httpclient Build fail-closed (ADR-044):** `Build()` returns `(Client, error)` and refuses compositions that would silently discard TLS material or a caller's `RoundTripper`.
- **Readiness sanitized by default (ADR-048; ADR-046's strict cache default is reversed by ADR-094 below):** every critical probe's 503 body serves a fixed `"<name> unavailable"` unless `HealthStatus.PublicErr` overrides it; the cache probe is critical only under an explicit `cache.critical: true`.
- **Delivered-empty `debug.allowedips` (ADR-078):** any delivery that decodes to NO entries — `DEBUG_ALLOWEDIPS=`, `allowedips: ""`, a separator-only value (`,`), or YAML null — fails configuration resolution; it used to wipe the loopback default and, with `debug.bearertoken` set, skip the IP whitelist while booting. An empty LIST (`allowedips: []`) stays legal as the deliberate token-only clear. Note the divergence from ADR-074/077: null is absence there, a wipe here. Other `[]string` keys are unchanged.
- **Log filter walks arrays; needles normalize (ADR-079):** a JSON body shaped `{"…":[{…}]}` no longer panics the log path at either door (`Interface()`, `WithFields`); a slice whose elements the filter rewrites emits as `[]any` (serialized output unchanged, typed nils included). Needle trim/drop-empty moved into `NewSensitiveDataFilter`, closing the `Options.LoggerFilterConfig` door where one empty needle masked every field — YAML `log.sensitivefields` was already normalized and is unaffected; the masking-disabled WARN now judges the effective list. Scheduler job-panic summaries read `panic (type: T)`: repoint alerts, the old match fails silently.
- **Client IP from observed hops only (ADR-080):** `server.ClientIP` answers with an identified untrusted hop or the peer it observed, never a caller-written value — every `X-Forwarded-For` line is read, brackets stripped, an unparseable hop stops the walk, an all-trusted chain yields the peer, and `X-Real-IP` is not consulted; all three `trustedproxies` keys reject a list that trusts an entire address family — a literal default route, a set covering one between its entries (`["0.0.0.0/1","128.0.0.0/1"]`), or the v4-mapped `::ffff:0.0.0.0/96` (the debug and scheduler keys previously accepted even a literal default route, which `server.trustedproxies` refused, making a DIRECT caller's headers authoritative; the set-coverage rule is new on all three), and `debug.allowedips` gains CIDR-syntax validation accepting bare addresses. Allowlists stay exempt. See `[C60.22]`.
- **Debug endpoints fail closed (ADR-049):** `RegisterDebugEndpoints` returns `error` and aborts startup when `debug.enabled: true` would expose an endpoint with neither `debug.allowedips` nor `debug.bearertoken` set; either key — or `debug.enabled: false` — satisfies the check.
- **Cache construction fails closed (ADR-054):** `ResourceManagerFactory.CreateCacheManager` returns `(*cache.CacheManager, error)`, so a cache the framework was told to build but could not — a negative `cache.manager.maxsize`/`idlettl` — aborts startup instead of a WARN plus a bare `nil` that registered no readiness probe. Absence (`cache.enabled: false`) is unchanged; an unreachable Redis at boot still only WARNs.
- **Database wiring fails closed (#892, ADR-050, ADR-051):** an enabled outbox/inbox without a usable ledger database, an unrecognized `connectionstring` scheme on the built-in connector, and any identity key delivered as an empty string each abort startup; a recognized scheme infers `database.type`.
- **Dead exported surface removed (ADR-052, ADR-053):** `jose.PolicyRegistry` (memoize `jose.ScanType` + `jose.ResolvePolicy` yourself, keyed on type AND direction) and `server.TestShortTimeout`/`TestMediumTimeout`/`TestLongTimeout` are gone.
- **OTel log-record identity (ADR-055, ADR-056):** top-level fields keyed `service.*`, `telemetry.sdk.*`, or `deployment.environment.name` reach OTLP as `app.<key>`; framework record attributes shrink to `log.type`, identity stays in `ResourceLogs.resource`.
- **Consumer-scoped AMQP args (ADR-058):** `ConsumeOptions`/`ConsumerOptions`/`ConsumerDeclaration` gain `Args`, forwarded to `basic.consume` — that is where `x-stream-offset` goes; `DeclareStreamQueue` sets only queue type + retention. A map field makes all three non-comparable: `==` and map-key use stop compiling.
- **Cache conditional release (ADR-060):** `cache.Cache` gains `CompareAndDelete`; every implementer must add it, including test doubles `go build` skips — use `go vet ./...`. Release locks with it, not `Delete`, and acquire with a positive TTL.
- **Role password control chars (ADR-061):** `PGRoleSpec.Validate` rejects CR/LF/NUL in `MigratorPassword`/`RuntimePassword` — match `errors.Is(err, migration.ErrPGRolePasswordHasControlChar)`; trim file-sourced secrets.
- **Database TLS fail-closed (ADR-062):** `database.tls.mode` must be a valid sslmode; cert/key/ca require `require`/`verify-ca`/`verify-full`; the block is rejected alongside `connectionstring` and (entirely) on Oracle.
- **App validates every config (ADR-064):** `app.NewWithConfig`/`Builder.WithConfig` run `config.Validate`; hand-built configs that violate it fail construction.
- **keystore.secretminlength pointer encoding (ADR-065, bounded by ADR-095):** `KeyStoreConfig.SecretMinLength` is `*int` (`new(n)` in Go literals) so absent (nil = 32) and explicit stay distinct on both doors; a hand-built config that left it unset enforces the 32-byte floor, and since ADR-095 an explicit value must be at least 32 — the `0` opt-out is rejected by `config.Validate`, and by `keystore.Module.Init` as a backstop for a hand-built `ModuleDeps` that never passed it.
- **Dead app lifecycle surface removed (ADR-067):** `MessagingInitializer` and `ConnectionPreWarmer` (constructors and methods included), `Options.Database` and `Options.MessagingClient` are gone; the eight debug response types are unexported with their JSON unchanged.
- **One delivery pipeline (ADR-068):** `messaging.StartConsumeSpan` is removed — a service driving its own consume loop starts its own span — and the AMQP `messaging.client.consumed.messages` counter is recorded at completion with `error.type` instead of at receive without it.
- **Emit-side traceparent validated (ADR-070 amendment):** `trace.InjectIntoHeaders` runs a PRE-SET `traceparent` — one your code put in `PublishOptions.Headers`, or one an outbox row persisted — through `ValidateTraceParent` before reusing it; precedence is unchanged (a valid pre-set value still outranks the context), but an invalid one falls through to the context parent then to a generated one, and the `tracestate` beside it is overwritten from the context or emptied. The `tracestate` beside an ACCEPTED pre-set traceparent is now left untouched, where the context's used to overwrite it. The outbound `X-Request-ID` is derived only from a 32-digit HEX trace-id. See `[C61.14]`.
- **Delivered-empty numeric and bool config (ADR-074, ADR-077):** an empty string bound to a numeric or bool key (`FOO=`, empty `secretKeyRef`) fails configuration resolution naming the key — at startup, or at first use for the CLI's `tenants.yaml` and a dynamic `DBConfigProvider` — instead of decoding as `0`/`false` — which flipped `database.pool.keepalive.enabled` off and made a failing `cache.critical` probe stop failing `/ready`; explicit values, unset, YAML omission and YAML null are unchanged.
- **Scheduler timeouts normalize (ADR-075):** `scheduler.timeout.shutdown`/`slowjob` default in `config.Validate` (30s/25s — hand-built configs move 30s → 25s), negatives fail validation, and `scheduler.Module.Init` requires a NORMALIZED `deps.Config` — non-nil, both timeouts positive — so a config assembled outside app construction must go through `config.Validate` first.
- **A tenant's cache errors are addressed to that tenant (ADR-076 amendment):** the per-key cache factory held the resource key and still reported the ROOT spelling, so for one tenant the startup door said `multitenant.tenants.acme.cache.redis.host` while the runtime door said `cache.redis.host` and its hint named `CACHE_REDIS_HOST` — a variable that configures the root cache and leaves that tenant broken. All four factory errors (nil config, `Enabled=false`, unsupported `type`, empty Redis host) now route through the exported `config.QualifyCacheConfigErrorForKey`, which the startup door calls too, so the doors cannot drift: `Field` reads `multitenant.tenants.<id>.cache.<leaf>` for the type and Redis-host errors and the bare `multitenant.tenants.<id>.cache` for the nil-config and `Enabled=false` ones, which name no leaf — so match the section as a prefix, not one full key — and a generated hint names `MULTITENANT_TENANTS_<ID>_CACHE_<LEAF>`, dropping the env half when the key does not round-trip (an id containing `_`). The empty key is the root and comes back UNTOUCHED, so single-tenant strings are byte-identical; `Category` never moves and messages are unchanged. `requalifyAction` widened with it — it reads the YAML key out of the hint instead of rebuilding it from `Field`, which is what lets the not-configured hint (`cache.enabled` under `Field` `cache`) travel, while a hand-written action and a hint naming a key outside the field stay untouched. Match the cache family, not equality. See `[C61.24]`.
- **Section-qualified config errors (ADR-076):** a non-root database section's `ConfigError.Field` names that section (`databases.reporting.host`, `multitenant.tenants.acme.database.host`); match with a database-scoped predicate, not equality and not a bare suffix — `cache.redis.host` ends in `.host` too. Root keeps the root spelling. The runtime door matches via the additive `ApplyDatabasePoolDefaultsForKey` (the old function is unchanged and still root-addressed), so a dynamic tenant is addressed like a static one, the manager stops wrapping, `Action` names the section's own env var (or none where none reaches the key), and the tenant cache, messaging and `NewMultiTenantError` fields join the same spelling (the per-key cache FACTORY followed on the E61 hop — see the ADR-076 amendment line below).
- **Response error details carry no request input (ADR-084):** `server.FieldError` loses `Value` — it was the rejected input for ANY failed tag — and its `Field` (with the message built from it) redacts the bracketed span, so a `dive`-validated map reads `Limits[*]` instead of the input key. A bind failure's `details.error` becomes a payload-free summary — the type-gated JSON decode summary, or the binding source plus the destination field by struct tag — never `bindErr.Error()`. Every response `error.details` map now requires `app.debug` AND a development `app.env` at the single `devDetails` funnel, extending `[C60.30]` to every status and to raw mode. messaging's safe-rendering primitives move to `internal/saferender` unchanged. See `[C61.1]`, `[C61.2]`.
- **Outbox ledger sequenced, laned and led (ADR-088):** every row gains `seq` (a per-ledger identity assigned at insert, which `FetchPending` now orders by instead of the TIE-prone `created_at`), `lane`, `stream` and `partition_key`, plus a companion `<table>_leader` table holding one row. Two behaviors move for EVERY enabled outbox, configured or not: one relay instance per ledger drains at a time — a cycle takes the leader row `FOR UPDATE NOWAIT` before fetching and probes it before each record, so a second replica logs `another instance leads this ledger` at DEBUG and does nothing, where both replicas used to publish the same rows — and a FAILED row parks its key's later rows for the cycle, neither publishing nor marking them, so their `retry_count` deliberately stops advancing (a dashboard reading that count as liveness sees a stall). The key is the tenant stamp for a stamped AMQP row, `exchange`+routing key otherwise, and stream+partition key on the stream lane. Compile-time: `config.OutboxConfig` gains `SuperStreams []string` and is no longer comparable, and `outbox.Store` gains `Lead`. With `autocreatetable` nothing to do; with MANAGED migrations run the `ALTER`, then the EXPLICIT `seq` backfill (an identity column populates existing rows in heap/rowid order, NOT `created_at` order, and the divergence lands on exactly the retried rows a backlog is made of), then the index — skipping the backfill drains the backlog once in an arbitrary order and nothing reports it. `outbox.tablename`'s last segment is bounded at 49 bytes so `idx_<name>_published` stays distinct under PostgreSQL's 63-byte truncation. `outbox.superstreams` lists the super streams the relay may publish to over the native streams lane; each listed name gets ONE publisher declared by the outbox, so a target it owns cannot also be published to directly by another module in the same process, and a target set without `messaging.streams.uri` fails startup. The relay also MOVES a row's persisted tenant stamp onto the publish context rather than replaying it as a header — the framework is the stamp's only writer (ADR-087), so a hand-written `x-tenant-id` in `OutboxEvent.Headers` no longer reaches the broker verbatim, though a consumer still reads the framework's. See `[C61.23]`.
- **Log filter masks inside opaque payloads (ADR-086):** the sensitive-data filter no longer stops at a byte slice or a string. A payload whose first non-space byte is `{` or `[` — `json.RawMessage`, `[]byte`, `[]json.RawMessage`, the `Bytes()` door, a JSON-looking string — is parsed, walked with the SAME needles, and re-encoded ONLY when something was masked, so a clean payload keeps its bytes while a masked one normalizes key order and whitespace: re-record any fixture pinning a masked body. Two shape rules catch key material no name needle can match: an object carrying `kty` has `d p q dp dq qi k oth` masked wherever it sits (matched exactly, never by substring), and a PEM block whose label ends in `PRIVATE KEY` is masked whole while a certificate stays readable. Fail-closed: a JSON-looking payload that will not parse, is not exactly one document, exceeds the depth limit, or exceeds the new `FilterConfig.MaxPayloadBytes` (64 KiB default; zero means the default, negative disables the door) renders as the mask value entirely. JWTs, XML, form-encoded bodies and the `Msg` text are deliberately not inspected. See `[C61.18]`.
- **Outbox refuses an unpublishable destination (ADR-033 amendment):** `outbox.Publish` runs the exported `messaging.ValidatePublishDestination` on the post-fallback exchange, the post-fallback routing key (an empty one still takes `EventType`) and the caller's header keys BEFORE `Store.Insert`, so a value over the 255-byte AMQP shortstr limit fails the call — `errors.Is(err, messaging.ErrInvalidPublishDestination)` under the `outbox:` prefix — with nothing written. `outbox.Module.Init` refuses an over-long `outbox.defaultexchange`, naming the key and the byte length. In the relay, `ErrInvalidPublishDestination` becomes a second POISON class beside undecodable headers: parked via `MarkDeadLettered` at `outbox.maxretries` instead of retried forever; connectivity (NACK, confirm timeout, not-connected, deadline) is unchanged. See `[C61.19]`.
- **User-named config sections must be env-reachable (ADR-090):** a key under `databases`, `multitenant.tenants` or `keystore.keys` must match `^[a-z0-9-]+$` — `config.Validate` rejects anything else with a `*ConfigError` whose `Field` is the key path and whose action says rename. `Load` lowercases a variable and maps `_` to `.`, so `databases.report_db` was addressable by no variable at all: alone `DATABASES_REPORT_DB_PORT` failed startup blaming a phantom `databases.report`, and beside a real `databases.report` it was applied to the SIBLING's subtree while `report_db` kept its YAML value — dropped where the remaining segments name no field, landing on the sibling's own setting where they do. Hyphen is legal (the resolver's tenant-ID grammar without its length bound), header maps are excluded, dynamic tenant IDs stay the resolver's business, and the env transform is unchanged. See `[C61.22]`.
- **Framework owns the PG Flyway URL (ADR-085):** for a PostgreSQL discrete-field config the framework builds `jdbc:postgresql://host[:port]/db?ApplicationName=<app.name>[&sslmode][&sslrootcert]` from `database.*` and passes `-url=`, silently outranking any `flyway.url` in your `flyway.conf`; the TLS WARN and the `DB_SSL*` export are gone and credentials stay env-delivered (argv is world-readable). Eight fail closed: `tls.cert`/`tls.key` (`ErrMigrationMTLSUnsupported` — the framework does not forward them as JDBC `sslcert`/`sslkey`); a `host` that is not an IP or plain DNS name (`ErrInvalidMigrationHost` — unescaped it ends the authority early, injecting params); a `port` below 0 or above 65535, `0` staying unset (`ErrInvalidMigrationPort` — a negative one silently took the driver default); a `tls.mode` outside the libpq six (`ErrInvalidMigrationTLSMode` — it was copied onto the URL verbatim; trimmed first and matched case-sensitively, exactly as `config.Validate` does, so ` require` normalizes and `Require` fails); a `tls.ca` without `verify-ca`/`verify-full` (`ErrMigrationTLSCARequiresVerify` — pgjdbc reads `sslrootcert` only under those two, so the CA was emitted and ignored; deliberately STRICTER than `config.Validate`, which admits `require`+ca because pgx honors it there); `tls.ca: system` (`ErrMigrationTLSCASystemUnsupported` — a libpq/pgx sentinel pgjdbc has no equivalent for, and the JVM trust store is a different trust set, so it is refused rather than remapped); a partial block or `tls.*` that cannot reach a URL (`ErrIncompleteMigrationTarget`); and `tls.*` beside a `connectionstring` (`ErrMigrationTLSWithConnectionString` — the framework does not parse DSNs, so keep TLS in the DSN for the runtime and put the migration's own on the `flyway.conf` URL, which must also name the SAME host and database or an encrypted migration lands on the wrong one). By validation scope: four bind every config — the mTLS pair, the host grammar, and both CA rules — because `config.Validate` admits those shapes (pgx honors them); the other four (port range, `tls.mode`, the partial block, and `tls.*` beside a `connectionstring`) repeat what `config.Validate` already rejects, so they are reachable only for dynamic-provider and CLI configs that never pass it. Oracle (where `database.tls` is rejected, not absent), a TLS-free `connectionstring`, and a type-only block without TLS keep the conf-owned URL. See `[C61.4]`.
- **Span sinks record errors by type (ADR-083):** `observability.RecordErrorByType` is the only framework spelling of "record an error on a span" — one `exception` event carrying `exception.type` (the outer `%T`) and NO `exception.message`, status `codes.Error` with that same type. An alert keyed on `exception.message`, or on a message-bearing span status description, for job, handler, HTTP-client or publish failures stops matching; the log line at each site still carries the message. See `[C61.3]`.
- **Upsert column keys: one rule, normalized (ADR-082 amendment):** `BuildUpsert`'s conflict, insert and update KEYS are trimmed, then judged by ONE rule on both vendors — a single column name (no qualifier, no function call, no empty name) carrying no quote of its own beyond a plain wrapping pair. PostgreSQL refuses `t.name`, `COUNT(*)` and an empty key it used to render; BOTH vendors refuse a doubled-quote key (`a""b`) Oracle accepted — an identifier argument carries no quoting, the door quotes, and there is no expression-key hatch here (the keys are strings) — a column name holding a quote needs a hand-written statement. One clause WIDENS on PostgreSQL, which refused every quoted key and now takes `"ID"` / `"count(*)"` like Oracle. The trimmed spelling is rendered AND compared, so a key written with surrounding spaces (` id `, spaces OUTSIDE any quoting) matches its `id` insert key, and a map holding both spellings is rejected naming both. PostgreSQL identity is the RENDERED identifier, so `ID` and `"ID"` are one column there — they render alike — while `id` and `ID` stay two. See `[C61.15]`.
- **RawExpression alias is a grammar, not a denylist (ADR-082 addendum):** an alias must be an UNQUOTED identifier (`sqllex.IsUnquotedIdentifier` — not `IsBareIdentifier`, which also admits the quoted reserved-word form); the six-substring denylist accepted everything it did not list, so `Alias: "x FROM users"` opened a clause. `ErrDangerousAlias` is DELETED — match `errors.Is(err, dbtypes.ErrInvalidAlias)`. Checked in `Validate()`, so it fails at `Expr()` AND `ToSQL()`. See `[C61.9]`.
- **Identifier arguments validated at every door (ADR-082):** `Insert`, `InsertWithColumns`, `InsertStruct`, `InsertFields` and `BuildUpsert` validate their TABLE argument against ADR-031 grammar — a bare or qualified name plus at most one alias — so a computed table needs an allowlist your own code owns; and both identifier renderers double an interior quote, so a name carrying one renders as that name instead of ending the identifier early (#1104). ADR-031 had excluded the Filter API by reading "parameterizes its values" as "is safe" — `f.Eq(column, value)` does the first for the value and neither for the column; `Select` and the INSERT column lists (`InsertWithColumns`, `.Columns`, `.SetMap`) now validate too — a `select` context adds the wildcard so `Select("*")` is unaffected, while a function or constant string moves to `qb.Expr()`, including the `EXISTS` idiom `Select("1")`; and every Filter and JoinFilter column joins them, validated through a single fallible funnel (`quoteColumnForQuery`) rather than per-door guards — on PostgreSQL that closes a LIVE hole, where the renderer emitted the column verbatim and `f.Eq("id = 1 OR 1=1 -- ", v)` built `WHERE id = 1 OR 1=1 -- = $1`. `Having` takes a predicate, not an identifier, and stays a raw-SQL door (#1146); a `RawExpression` STRUCT LITERAL is validated where it is consumed, so the alias denylist `qb.Expr()` applies is no longer skippable — its SQL body still is not judged; `cols.As(alias)` validates too but PANICS with `*dbtypes.InvalidAliasError` — it returns a `Columns`, not a builder, so it has no deferred-error channel, and the empty-alias panic value changes from a string (#1150). See `[C60.24]`–`[C60.29]`.
- **Observability teardown is best-effort (ADR-029 amendment):** the observability phase of `App.Shutdown` no longer contributes to the error `App.Run()` returns. A provider `Shutdown` failure of any kind is logged once at WARN (`Observability shutdown failed; telemetry may have been lost`) with the error and the phase duration, and shutdown proceeds to the closers; it used to log at ERROR and append `observability: <err>`, so a deployment whose collector was down exited non-zero from a graceful shutdown. Phase ORDER, the preceding `ForceFlush` and its WARN, and every other phase's error handling are unchanged. Repoint alerts keyed on the old ERROR line or on a non-zero exit; size `server.timeout.shutdown` above `observability.*.export.timeout` to KEEP the telemetry. See `[C61.20]`.
- **Streams lane is opt-in at the build graph (ADR-091):** `app` no longer imports `messaging/streams`. A process that wants the native stream protocol must import that package (a blank import is enough); `init` registers the runtime factory. `messaging.streams.uri` set without that import fails startup naming it (`app.ErrStreamsNotLinked`); no URI and no import starts clean. `app.StreamDeclarer` and `ModuleRegistry.DeclareStreams` are removed — implement `DeclareStreams(*streams.Declarations)` as before, or name `streams.StreamDeclarer`. Hold port types (`HeldMessage`, `HoldLedger`, `HoldReplayer`) are aliases of the same seam types, so inbox no longer imports the vendor package. See `[C61.25]`.
- **The literal `Local` timezone is refused (ADR-093):** `scheduler.timezone`, `database.timezone` and every `databases.<name>.timezone` / `multitenant.tenants.<id>.database.timezone` fail `config.Validate` when set to exactly `Local` — `time.LoadLocation` resolves that spelling to the host zone, making it an undocumented second spelling of the `"-"` opt-in. The `*ConfigError` names the key and reads `timezone "Local" is not accepted; use "-" for the documented opt-out or an explicit IANA zone`. `"-"`, `UTC`, empty and every IANA name are unchanged; `local`/`LOCAL` were already refused as unknown zones. See `[C62.1]`.
- **Cache readiness non-critical by default (ADR-094):** an absent `cache.critical` — and a nil `*config.Config` — now leaves the cache probe informational: `/ready` reports `cache: "unhealthy"` in a `200` body through a Redis outage where v0.61.0 answered `503` on every replica at once, and logs no `Readiness check failed` line for it. Only an explicit `cache.critical: true` opts into readiness gating; an explicit `false` is the default spelled out and no longer WARNs at startup. Reverses ADR-046's default; ADR-048's sanitized `503` body, the absence of a registered koanf default, and the delivered-empty rejection (ADR-077) are unchanged. Amended (#1316): `config.CacheConfig.Critical` is a plain `bool` — `Critical: new(true)` no longer compiles, write `Critical: true`; YAML and env spellings are untouched. See `[C62.2]`.
- **keystore secret-length floor is mandatory (ADR-095):** a set `keystore.secretminlength` below 32 — the former `0` opt-out included — fails `config.Validate` with a `*ConfigError` on that key naming the floor and the ADR, judged before the empty-keys return; unset still means 32, a set value can only raise it, the field stays `*int`, and ADR-065's two startup WARNs are deleted. A symmetric secret shorter than 32 bytes has no keystore path — load such a partner key outside `keystore`. See `[C62.3]`.
- **Header-sourced event ids must match `^[A-Za-z0-9_-]{1,128}$` (#1353, ADR-097 §4):** `inbox.ProcessOnce` validates every id before the ledger, sealed or not — a non-conforming one is an error wrapping `messaging.ErrInvalidEventID`, no row written, a nack-without-requeue on first delivery. Framework-minted UUIDs comply; re-mint hand-set ids or move the event to the sealed Typed door. `Meta.DedupKey()` returns the validated `x-outbox-event-id` (plain `T`) or `<SignFamily>:<jti>` (sealed `T`, #1359: admitted at the ledger only under the sealed door's own context marker, `messaging.IsSealedDelivery`) and `Meta.Sealed()` is `false` for a plain typed consumer; `outbox.HeaderEventID` aliases `messaging.HeaderEventID`; the dedup short-circuit records `inbox.dedup.hits` plus one INFO line carrying the id's length, never its value; `inbox.retentionperiod` is the replay window. See `[C63.2]`.
- **Typed publish door replaces raw byte publishing (ADR-096):** `messaging.Client.Publish` and `messaging.AMQPClient.PublishToExchange` are removed from the module-facing types (`deps.Messaging(ctx)`, `JobContext.Messaging()` — the latter now typed `messaging.AMQPClient`) with no escape hatch, `PublishOptions` is unexported and `ValidatePublishDestination` takes `(exchange, routingKey, headers)`; declare `messaging.DeclareTypedPublisher[T](decls, opts)` in `DeclareMessaging` and publish with `h.Publish(ctx, client, evt)` — a client the framework did not build fails with `ErrPublishDoorUnavailable`. `testing/mocks` loses the byte doubles (`Publish`, `PublishToExchange`, `PublishedFrame`, `ExpectPublish*`); store the handle behind the additive `messaging.EventPublisher[T]` and inject `messaging/testing.CapturePublisher[T]`. `streams.Publisher.Publish` is unchanged. See `[C63.1]`.
- **Query builder grows four clauses (ADR-098):** `types.SelectQueryBuilder` gains `ForUpdate()`, `ForUpdateNoWait()` and `SubqueryColumn(sub, alias)`; `types.UpdateQueryBuilder` gains `SetExpr(column, expr, args...)` — a consumer type that IMPLEMENTS either interface stops compiling until it adds them; callers are unaffected. A row lock is refused on Oracle beside `Limit`/`Offset` (`ErrRowLockWithPagination`) and as a subquery; `SetExpr` is a raw-SQL door (annotate every call site); a table-less Oracle `SELECT` renders `FROM dual`. See `[C63.3]`.
- **Subject case-fold twin refused on the serialized bytes (ADR-097 amendment, #1408):** `jose/sealed.Seal` — and the new `SealDocument` — refuse a document carrying a top-level member whose name case-folds to the Subject member's without equalling it, with `SEAL_DOCUMENT_INVALID`; `encoding/json` decodes members case-insensitively, so such a twin let a consumer read the clear member instead of the sealed one. `ScanType` enforced this on DECLARED fields only, so a seal-tagged type whose own `MarshalJSON` emitted `Card` beside `card` sealed in v0.62.0 and fails at publish now — rename the clear member or drop it from the marshal output; never rename the Subject, whose name is the signed `sp` entry. `Open` and every already-sealed message are unaffected. See `[C63.5]`.
- **One column order for map-shaped doors, one inequality spelling (ADR-099, #1185/#1200):** both `SetMap` doors render their columns in the CALLER's name order through one shared helper (`quotedColumnsInNameOrder`), so a multi-column Oracle `SetMap` UPDATE whose keys include a quoted reserved word emits `SET id = :1, "level" = :2, "size" = :3` instead of leading with `"level"`, and the bind arguments move with the columns; PostgreSQL output, the error text, the validation funnel and the padded-duplicate-key behaviour are unchanged, and `BuildUpsert` keeps its own ordering. In the same change `jf.NotEq(col, scalar)` and `jff.NotEqColumn(l, r)` render `<>` rather than `!=`, matching `f.NotEq`; nil and slice operands are untouched. Nothing here is compiler-caught — the population is your golden SQL and query-text assertions. See `[C64.1]`.
